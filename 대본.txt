# JavaScript `??` Nullish 병합 연산자 발표 대본

## 슬라이드 1 — nullish 병합 연산자란?

안녕하세요. 지금부터 자바스크립트의 **nullish 병합 연산자 `??`**에 대해서 설명하겠습니다.

먼저 `??`는 여러 값 중에서 **실제로 사용할 수 있는 값을 찾아주는 연산자**라고 이해할 수 있습니다.

기본적인 형태는 `a ?? b`입니다.

여기서 `a`가 `null`도 아니고 `undefined`도 아니라면 `a`를 그대로 사용합니다.

반대로 `a`가 `null`이나 `undefined라면` `b`를 사용합니다.

쉽게 말하면 **왼쪽에 정상적인 값이 있으면 그대로 사용하고, 값이 없을 때만 오른쪽의 기본값을 사용하는 것**입니다.

그래서 `??`를 사용할 때는 **null과 undefined를 구분해서 보는 것이 중요합니다.**

---

## 슬라이드 2 — `??` 없이 같은 기능을 구현하면?

이번에는 `??`를 사용하지 않고 같은 기능을 구현하는 방법을 보겠습니다.

예를 들어 `x = a ?? b`라는 코드가 있다면,

`a`가 `null`이 아니고 동시에 `undefined`도 아닌지를 확인해야 합니다.

그래서

```js
x = (a !== null && a !== undefined) ? a : b;
```

와 같이 작성할 수 있습니다.

먼저 `a !== null`을 확인하고,

그리고 `a !== undefined`인지도 확인합니다.

두 조건이 모두 맞으면 `a`를 사용하고,

조건이 맞지 않으면 `b`를 사용합니다.

즉, `??`는 이렇게 여러 조건을 확인해야 하는 코드를 **더 짧고 간단하게 표현할 수 있도록 해주는 연산자**라고 볼 수 있습니다.

---

## 슬라이드 3 — 여러 값 중 첫 번째 확정값 찾기

이번에는 `??`를 여러 번 사용하는 예제를 보겠습니다.

코드를 보면 `firstName`, `lastName`, `nickName` 세 개의 변수가 있습니다.

여기서 `firstName`과 `lastName`은 `null`이고,

`nickName`에는 `"바이올렛"`이라는 값이 들어 있습니다.

그리고 다음과 같이 작성했습니다.

```js
alert(firstName ?? lastName ?? nickName ?? "익명의 사용자");
```

`??`는 왼쪽부터 차례대로 확인합니다.

먼저 `firstName`은 `null`이기 때문에 넘어갑니다.

다음 `lastName`도 `null`이기 때문에 넘어갑니다.

그리고 `nickName`에서 `"바이올렛"`이라는 값을 찾았기 때문에 이 값을 사용합니다.

따라서 최종 결과는 **"바이올렛"**이 됩니다.

즉, 여러 값 중에서 **null이나 undefined가 아닌 첫 번째 값을 찾는 방식**으로 사용할 수 있습니다.

---

## 슬라이드 4 — `??`와 `||`의 차이

이번에는 `??`와 `||`의 차이를 알아보겠습니다.

두 연산자는 비슷하게 기본값을 지정할 때 사용할 수 있지만, **값을 판단하는 기준이 다릅니다.**

먼저 `||`는 왼쪽부터 확인하면서 **truthy한 첫 번째 값을 반환**합니다.

반면 `??`는 **null과 undefined가 아닌 첫 번째 값을 반환**합니다.

여기서 중요한 차이는 `0`, `false`, 빈 문자열 같은 값입니다.

`||`에서는 이런 값들을 falsy로 판단하기 때문에 다음 값으로 넘어갈 수 있습니다.

하지만 `??`에서는 `null`과 `undefined`만 특별하게 취급합니다.

따라서 **값이 0이나 false여도 그것을 정상적인 값으로 사용해야 하는 상황이라면 `??`가 유용합니다.**

---

## 슬라이드 5 — `0`에서는 어떤 차이가 있을까?

앞에서 설명한 차이를 `0`을 이용해서 확인해보겠습니다.

먼저

```js
let height = 0;
```

이라고 값을 지정했습니다.

그리고

```js
height || 100
```

을 실행하면 결과는 **100**이 됩니다.

왜냐하면 `||`는 `0`을 falsy로 판단하기 때문입니다.

반면

```js
height ?? 100
```

을 실행하면 결과는 **0**입니다.

`??`는 `0을 null이나 undefined로 판단하지 않기 때문입니다.

즉, `0`도 실제로 의미가 있는 값이라면 그대로 사용합니다.

그래서 `||`는 **truthy와 falsy를 기준으로 판단**하고,

`??`는 **null과 undefined를 기준으로 판단**한다고 기억하면 됩니다.

---

## 슬라이드 6 — 기본값을 할당할 때

이번에는 `??`를 이용해서 변수에 기본값을 할당하는 방법입니다.

예제에서는

```js
height = height ?? 100;
```

이라고 작성했습니다.

이 코드는 `height`가 `null`이나 `undefined`라면 **100을 넣어주고**,

그렇지 않다면 원래 값을 그대로 유지합니다.

예를 들어 `height`가 `null`이라면 결과는 100이 됩니다.

`undefined`인 경우에도 마찬가지로 100이 됩니다.

하지만 `height`가 0이라면 이야기가 달라집니다.

0은 `null`이나 `undefined`가 아니기 때문에 **원래 값인 0을 그대로 유지합니다.**

따라서 이 코드는 **값이 없는 경우에만 기본값을 넣어주는 방법**이라고 이해하면 됩니다.

---

## 슬라이드 7 — 연산자 우선순위

다음은 `??`를 사용할 때 알아두면 좋은 **연산자 우선순위**입니다.

`??`의 연산자 우선순위는 비교적 낮기 때문에 여러 연산자를 함께 사용하는 경우에는 주의해야 합니다.

PPT의 예제처럼

```js
let area = (height ?? 100) * (width ?? 50);
```

에서는 괄호를 사용해서 먼저 어떤 값을 선택할 것인지 명확하게 표현했습니다.

여기서는 `height`가 없으면 100을 사용하고,

`width`가 없으면 50을 사용한 다음 두 값을 곱합니다.

특히 곱셈 같은 연산자는 `??`보다 우선해서 계산될 수 있기 때문에 복잡한 표현식에서는 **괄호를 사용하는 것이 좋습니다.**

즉, 괄호를 사용하면 코드의 의도를 명확하게 보여줄 수 있습니다.

---

## 슬라이드 8 — `??`와 `&&`, `||`를 함께 사용할 때

이번에는 `??`를 사용할 때 주의해야 하는 부분입니다.

`??`는 `&&`나 `||`와 **괄호 없이 함께 사용할 수 없습니다.**

예를 들어

```js
let x = 1 && 2 ?? 3;
```

처럼 작성하면 문법 오류가 발생합니다.

따라서 이런 경우에는 괄호를 사용해서 어떤 부분을 먼저 계산할 것인지 명확하게 만들어야 합니다.

예를 들어

```js
let x = (1 && 2) ?? 3;
```

이라고 작성하면 정상적으로 동작합니다.

먼저 `(1 && 2)`를 계산하고 그 결과인 `2`를 `??`가 확인합니다.

2는 `null`이나 `undefined`가 아니기 때문에 최종 결과는 **2**가 됩니다.

따라서 `??`와 `&&`, `||`를 함께 사용해야 한다면 **괄호를 사용한다**고 기억하면 됩니다.

---

## 슬라이드 9 — 정리

마지막으로 지금까지 배운 내용을 정리해보겠습니다.

첫 번째로, `??`는 **null이나 undefined가 아닌 첫 번째 값을 찾는 연산자**입니다.

두 번째로, 변수의 값이 없을 때 **기본값을 지정할 수 있습니다.**

예를 들어

```js
height = height ?? 100;
```

이라고 하면 `height`가 `null`이나 `undefined`일 때만 100을 사용합니다.

세 번째로 `||`와의 차이도 기억해야 합니다.

`||`는 **truthy와 falsy를 기준으로 판단**하고,

`??`는 **null과 undefined만 기준으로 판단**합니다.

그래서 `0`, `false` 같은 값을 정상적인 값으로 유지해야 할 때 `??`를 사용할 수 있습니다.

마지막으로 복잡한 표현식에서는 **괄호를 사용해서 계산 순서를 명확하게 하고**, `??`를 `&&`나 `||`와 함께 사용할 때도 괄호를 사용해야 합니다.

이상으로 **nullish 병합 연산자 `??`에 대한 설명을 마치겠습니다.** 감사합니다.
